Programiz PRO users learned a language, then left — the average subscriber stuck around for just 3 months. I led design on PRO Challenges, a gamified coding-challenges feature built to give people a reason to keep coming back, from the first sketch through a public alpha launch.

Problem

Average user lifetime on Programiz PRO was 3 months.

Users came into the platform, learned a language, then left. There wasn't a reason to stay once the course was finished.

Two forces pulling users away

1. User retention

Users finished a course, then had no reason to return Avg. lifetime on Programiz PRO: 3 months

2. AI learning

"Why learn from a platform when ChatGPT could teach you everything?" AI tutors becoming a real substitute for structured lessons

Goal: increase user retention.

Solution

Gamification + community, packaged as PRO Challenges.

Instead of another course, we built a standing reason to come back: a library of coding challenges with XP, a leaderboard and streaks — the kind of loop that keeps people returning after the lessons are done.

Process

Designing a reward system from scratch: what it's called, what it pays, how it's calculated.

A gamification layer only works if the reward feels real. Before any screen got designed, three questions had to be answered: what is the reward called, how many points does each challenge pay, and how is that number calculated.

The whole feature had one month from concept to launch. To hit that, I made a deliberate call: reuse Programiz's existing UI patterns — the course page layout and the Playground dashboard — instead of designing new ones from scratch.

One month to build
↓
Reuse existing UI — course page + Playground dashboard

We shipped to a private alpha, announced publicly: for a limited time PRO Challenges was free to everyone, and the first 100 people to complete every alpha challenge would get a Programiz PRO subscription voucher — 50 vouchers, given away to drive first use.

Challenge

Reusing the Playground's UI made Challenges disappear into it.

The speed bet paid off on timeline, but the feedback after launch was clear:

What worked Users enjoyed the platform.
What didn't Users saw Challenges as a whole separate entity, not part of Programiz PRO.
Why They kept associating its features with the existing Playground, because of the identical, reused design.

The old design nested Challenges inside the Playground's own sidebar — a sub-item next to Leaderboard, sharing its shell. It read as a mode of an existing tool, not a feature of its own.

Old — Challenges nested inside the Playground sidebar
↓
New — a single, dedicated Python Challenges page with its own top-level nav item

Moving everything to one page made it more coherent to native Programiz PRO — and it's okay to pivot from an idea if it doesn't work out.

What I learned

There's no right solution, just a solution — so make it simple.

Reusing existing UI was the right call for the deadline, and the wrong call for clarity — both were true at once, and only real usage after launch surfaced which one mattered more. Being willing to pivot off a design that isn't working, instead of defending it, is what actually got Challenges to feel like part of Programiz PRO.
